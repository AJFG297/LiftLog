# Capability map

Internal capability instructions live in `../capabilities/<name>/index.md`.
Read the selected index in full before execution.

The provider may supply an installed skill with the same purpose. Use it only
when it preserves the A-stack playbook's completion contract. Otherwise use the
internal capability.

| Capability | Contract |
|---|---|
| `how` | Trace current runtime flow, ownership, key types, and placement before critique. |
| `why` | Reconstruct motivation from primary evidence and distinguish fact from inference. |
| `recall` | Rebuild current topic state from scoped history and live repository state. |
| `blast-radius` | Find the decisive safety assumption and prove it by running code when possible. |
| `architect` | Compare distinct caller-first interfaces before implementing across a seam. |
| `arena` | Run competing attempts, cross-judge, choose a base, graft, and verify. |
| `swarm` | Partition coverage or declared races and aggregate explicit outcomes. |
| `interrogate` | Run independent adversarial reviews and apply lead judgment without auto-fixing. |
| `tdd` | Prove the focused test red for the intended reason, implement, then prove green. |
| `show-me-your-work` | Keep an append-only decision trail with evidence pointers. |
| `figure-it-out` | Design and execute a bespoke auditable playbook when standard routes do not fit. |
| `create-verification-skill` | Create and prove a project-local real-application verification recipe. |
| `maintain-verification-skill` | Audit that recipe against source and one live pass. |
| `no-comments` | Review comments independently and encode real constraints in code, types, or tests. |
| `technical-writing` | Write one document mode with unambiguous instructions and stable vocabulary. |
| `unslop` | Remove formulaic prose while keeping the author's actual voice. |
| `reflect` | Propose durable workflow improvements from a completed run, subject to user approval. |
