# Aidan's working preferences

Apply these preferences across repositories unless local instructions conflict.

- Explain the affected system before changing it when ownership or behavior is
  not obvious.
- Review conclusions skeptically. Separate evidence, inference, and judgment.
- Prefer the smallest honest design. Delete pass-through layers and speculative
  configuration before adding abstractions.
- Use vertical slices that remain runnable and reviewable.
- Treat tests and runtime evidence as part of the design.
- Preserve handoff continuity. Do not redo completed work when a durable trail
  identifies the resume point.
- Ask for product intent rather than silently selecting a consequential meaning.
- Proceed on reversible implementation choices after intent passes.
